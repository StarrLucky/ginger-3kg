# ginger-3kg — учёт еды по фото и тексту

Личный трекер питания: FastAPI + SQLite на Raspberry Pi, веб-приложение без сборки и
слой распознавания еды внутри бэкенда.

Сфотографировал тарелку или написал «180 г гречки и куриная грудка» — получил черновик
с БЖУ, проверил глазами, сохранил. Ничего не записывается без подтверждения человеком.

План развития и обоснования решений — в [WEBAPP.md](WEBAPP.md). Этот файл про то,
как запустить и что где лежит.

## Как устроено

Запрос проходит два шага, и это разделение — главное архитектурное решение.

**Шаг 1, `recognize.py`** — модель отвечает, *что съели, сколько и что в этом
содержится*. Питательность она даёт **на 100 г**, а не на порцию: так число становится
свойством еды, его можно кэшировать по английскому `lookup_query` и масштабировать
арифметикой. Провайдер — конфиг, а не архитектура: Anthropic, Gemini и локальная модель
через Ollama прячутся за одним протоколом.

**Шаг 2, `nutrition.py`** — собирает итоговые числа по приоритету:

1. `overrides.json` — правка человека, последнее слово;
2. кэш в SQLite — для брендового по запросу с брендом, для остального по `lookup_query`;
3. Open Food Facts — только брендовое: там числа с этикетки конкретного продукта;
4. `per_100g` от модели — основной источник для обычной еды;
5. `needs_manual` — ненайденное помечается честно, а не заполняется нулями.

У каждой позиции есть `source_ref` (`model: buckwheat groats, cooked`,
`OFF: Ehrmann High Protein`, `override`), который виден на экране правки — всегда понятно,
откуда взялась цифра.

> **Почему числа даёт модель, а не справочник.** Изначально было наоборот, ради защиты от
> выдуманных чисел. Замер показал, что ошибка сопоставления крупнее: USDA находил
> «кофе с молоком» как *Candies, milk chocolate coated* — 1098 ккал вместо ~45. Разбор
> в WEBAPP.md §1.3++. USDA убран из рабочего пути; `usda_lookup()` оставлена как базовая
> линия для будущего замера.

### Каталоги

```
food_api/
  api.py              FastAPI: эндпоинты, авторизация, схема БД
  recognize.py        шаг 1 — провайдеры модели за общим протоколом

  nutrition.py        шаг 2 — источники чисел, кэш, масштабирование

  make_icons.py       иконки PNG без зависимостей
```

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp food_api/.env.example food_api/.env    # заполнить FOOD_API_KEY и ключ модели
make hooks                                 # pre-commit со сканером секретов
```

```bash
cd food_api
FOOD_API_KEY=... GEMINI_API_KEY=... RECOGNIZE_PROVIDER=gemini COOKIE_SECURE=0 \
  ../.venv/bin/python -m uvicorn api:app --port 8080
```

Приложение — на `http://127.0.0.1:8080/app/`, вход по `FOOD_API_KEY`.

`COOKIE_SECURE=0` нужен только для локального http: иначе браузер не сохранит
Secure-куку и вход молча не сработает. На проде не трогать.

## Настройки

Полный список с пояснениями — в [`food_api/.env.example`](food_api/.env.example).
Здесь то, что чаще всего удивляет.

**`RECOGNIZE_PROVIDER`** — список через запятую, порядок и есть порядок фолбэка.
У элемента можно указать модель через двоеточие:

```
RECOGNIZE_PROVIDER=gemini:gemini-3.5-flash-lite,gemini:gemini-3.6-flash
```

Это не украшение. Квота бесплатного тарифа Gemini — **20 запросов в сутки на модель**,
и перебор нескольких моделей единственный способ прожить день, не платя. Для ежедневного
учёта этого всё равно впритык: четыре приёма пищи плюс правки съедают квоту. Оплата в
Google AI Studio обходится примерно в $6 в год.

Семейство `gemini-2.5-*` снято для новых ключей и отвечает 404 — значения из старой
документации на свежем ключе не работают.

**`USDA_API_KEY`** рабочему пути не нужен, см. врезку выше.

**`TRUST_CLIENT_IP_HEADER`** — заполнять, только если перед сервисом реально стоит
прокси, который этот заголовок перезаписывает (Cloudflare: `CF-Connecting-IP`). Иначе
его подставит сам клиент и обойдёт счётчик попыток входа. Пустым оставлять безопасно.

## Авторизация

Два пути, оба ведут к одному ключу:

- **заголовок `X-API-Key`** — им ходят Custom GPT, Apple Shortcut и garmin-sync;
- **кука `session`** — её получает веб-приложение через `POST /auth/login`.

В куке лежит случайный токен, а не сам `FOOD_API_KEY`: утёкшую куку можно отозвать через
`/auth/logout`, не трогая ключ, которым ходят интеграции. Сессии живут год и проверяются
на сервере, а не только через `max-age`. Вход ограничен пятью попытками с адреса.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/recognize` | фото или текст → черновик с БЖУ, **ничего не сохраняет** |
| `POST` | `/logs` | записать приём пищи, возвращает пересчитанный день |
| `GET` | `/day`, `/days` | день и диапазон с прогрессом по целям |
| `DELETE` | `/logs/{log_id}` | убрать запись целиком |
| `POST` | `/targets` | цели по калориям и макросам |
| `POST` | `/activities`, `/activities/import` | активность, в том числе из Garmin |
| `DELETE` | `/activities/{activity_id}` | убрать активность |
| `GET` | `/products` | поиск в Open Food Facts, им пользуется Custom GPT |
| `GET` | `/export/pending`, `POST` `/export/ack` | очередь выгрузки в Apple Health |
| `POST` | `/auth/login`, `/auth/logout`, `GET` `/auth/status` | сессия веб-приложения |
| `GET` | `/health` | без авторизации |

Черновик от `/recognize` принимается в `/logs` без единой правки — списки нутриентов
совпадают поле в поле, и это закреплено тестом.

## Тесты

```bash
make check     # ruff + pytest
make secrets   # сканер секретов по всей истории
```

214 тестов на Python и 21 на фронтенде. Фронтенд прогоняется через Node с заглушкой DOM
(`food_api/webapp/tests/run.mjs`) — сборки нет, поэтому ломаться будут не типы, а пути,
и это закрыто отдельно: ссылки в `index.html`, список кэша в `sw.js`, импорты ES-модулей,
совпадение полей экрана правки со схемой `POST /logs`.

**Чего тесты не покрывают:** поведение в настоящем браузере — вёрстку, камеру,
`createImageBitmap`, регистрацию service worker. Это проверяется только на устройстве.

Принятая здесь практика — проверять новый тест мутацией: намеренно сломать код, который
он защищает, и убедиться, что тест падает. Несколько раз это показало, что зелёный тест
не проверял ничего.

## Развёртывание

Контекст сборки Docker — каталог `food_api/`:

```bash
cd food_api && docker compose up -d --build
```

Образ копирует `api.py nutrition.py recognize.py recognize_prompt.md overrides.json`
и каталог `webapp/`. База — общий с Custom GPT файл `food.db`, поэтому включены
`journal_mode=WAL` и `busy_timeout`: два процесса-писателя без этого дают
«database is locked».

Доступ снаружи ещё не настроен. Рекомендация и готовая конфигурация Cloudflare Tunnel —
в WEBAPP.md §2.6; ngrok на бесплатном тарифе показывает заглушку перед HTML-трафиком,
и для запуска с экрана «Домой» это ломает ощущение приложения.

## Секреты

Три слоя: pre-commit хук (`make hooks`), джоба в CI по всей истории и push protection на
стороне GitHub. Конфигурация gitleaks — в `.gitleaks.toml`, там же allowlist для строк
вида `usda_api_key=USDA_API_KEY`, где значение — имя переменной, а не ключ.

Хук закрыт «на отказ»: нет gitleaks — коммит не проходит, а не проходит молча.
